# TECHNICAL DISCLOSURE — omni-spec: a standards library built from the specification text, with a conformance oracle per module

Author: Juan Carlos De Santiago, with the Sovereign Raptor fleet (AI-assisted). Date of disclosure: 2026-10-16.

## 1. Problem
Software that renders documents, plays media or edits files needs many format decoders. Taking them from existing projects brings
their licences, their code history and their unstated behaviour. We wanted every module to have one auditable origin: the published
standard. That needs a method which (a) writes code from the text, (b) shows where each rule came from, and (c) measures agreement
with the standard without reading another implementation.

## 2. Method
1. **Spec first.** For each module a page records the standard, its version, and the sections implemented (`docs/<module>.md`);
   the source cites the section beside the rule it governs (for example `LB13` in the line-breaking engine, `§4.1.2` in SHA-256).
   Choices the text leaves open are written down as "behaviour choices" (for example GIF pixels outside frame 0, JSON numbers that
   overflow to infinity), so a reader knows where the code is a decision and where it is the standard.
2. **Tables from the text.** Data tables are generated by scripts in `tools/` from the standard's own data or text (Unicode data files,
   the RFC 7932 dictionary and context tables, the RFC 6716 SILK tables, the WHATWG named references) and each generated table is
   checked against values the standard prints (for example the Brotli dictionary has 122,784 bytes and a published CRC-32) before the
   file is written. The generator marks its output `@generated`.
3. **Oracle per module, in one of three forms.**
   - *Official conformance files* run directly: LineBreakTest, GraphemeBreakTest, BidiTest, BidiCharacterTest (Unicode 18.0.0), the
     html5lib tokenizer tests, JSONTestSuite, the NIST SHA-256 examples, the RFC 8251 Opus vectors.
   - *A second implementation run as a separate process* on deterministic synthetic inputs, with only its output compared (Pillow for PNG,
     GIF, JPEG, WebP; the Python brotli and zlib modules; fontTools and HarfBuzz for fonts; Info-ZIP and LibreOffice for archives and
     Office files). The input generators, the output hashes (FNV-1a 64 or SHA-256) and the pass rule are kept in `tools/` and `tests/data/*.tsv`.
   - *A state check inside the standard.* For Opus the test vectors carry the reference decoder's final range coder state per packet; a
     decoder that decodes every symbol correctly ends each packet with the same state, so this is an exact test of the entropy-decoded
     symbols without comparing audio. SILK parsing is exact by this check on all packets without redundancy.
4. **Stream-independent decoding.** The WebM / Matroska demuxer is written so that any chunking of the input gives the same event
   sequence (needed for Media Source Extensions); the tests feed every chunk size from 1 to 333 bytes and an unknown-size cluster.
5. **Fuzz without panics.** Each decoder returns `Err` on malformed input; tests flip bits, truncate and feed random bytes and require no panic.

## 3. Data layout
Plain Rust modules, no dependencies. Generated tables are sorted run lists or packed arrays looked up by binary search
(`uax14_tables.rs` holds 4,237 code-point runs). Decoders take `&[u8]` and return owned values; the streaming demuxer keeps its own
buffer. Large inputs are bounded (Brotli output defaults to 256 MiB).

## 4. Measured (one Intel i5-8365U laptop, 2026-10-16; `results/`)
113 tests in 24 test binaries, 0 failures. Line breaking 19,346/19,346; grapheme clusters 853/853; bidirectional 770,241 + 91,707;
HTML tokenizer 6,941/6,941; JSONTestSuite 95 accept + 188 reject; font tables 14,094 rows; WOFF2 40 fonts, 520 tables equal; WebP
lossless 10/10; Opus framing exact on 12 vectors and SILK final range exact on 3 whole vectors.

## 5. What is not claimed
No performance claim (the Brotli and inflate decoders are bit-serial). No claim that the code differs from any open implementation:
the clone check against open implementations has not been run. Parts of the table above need data this repository does not ship
(`DATA.md`); some checks passed on 2026-10-16 with part of their corpus absent (`STATUS.md`). Opus CELT audio, WebP lossy, HTML tree
construction and OpenType shaping beyond kerning and ligatures are not implemented.
