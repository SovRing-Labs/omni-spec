# ooxml — Office Open XML packages, spreadsheets and documents (ECMA-376 5th ed. = ISO/IEC 29500)

- **Spec:** ECMA-376 Office Open XML File Formats, 5th edition (Part 1 2021, Part 2 2021), identical in content to ISO/IEC 29500-1:2016 / 29500-2:2021, https://ecma-international.org/publications-and-standards/standards/ecma-376/
  - Part 2 Open Packaging Conventions: §9.1 part names, §9.3 relationships, §10.1.2 content types stream, §10.2 ZIP mapping, Annex C (ZIP subset).
  - Part 1 §18 SpreadsheetML: §18.2 workbook (sheets, workbookPr date systems), §18.3 worksheet (sheetData, row, c, v, is, f, sheetViews/pane, cols, autoFilter), §18.4 shared string table, §18.8 styles (numFmts, cellXfs, built-in formats §18.8.30), §18.17.4.1 date serial values, §18.18.11 ST_CellType, §22.9.2.19 ST_Xstring escapes.
  - Part 1 §17 WordprocessingML: §17.3 paragraphs / runs / run properties / breaks, §17.4 tables (gridSpan, vMerge, tblHeader), §17.5.2 structured document tags, §17.7 styles (basedOn, outlineLvl, numPr), §17.9 numbering (abstractNum, lvl numFmt / start, lvlOverride / startOverride), §17.11 footnotes and endnotes, §17.13.5 tracked insertions / deletions, §17.16 hyperlinks and HYPERLINK fields; §20.4 DrawingML pictures (wp:inline / wp:anchor, docPr, extent, a:blip); Part 2 §11 core properties (dc:title).
- **Code:**
  - `src/ooxml/opc.rs` — `Package::{open, part, part_names, has_part, content_type, rels, main_part, related}`, `PackageWriter::{add_part, add_rel, default_type, finish}`, `resolve`, `normalize`, `rels_part_for`, `rel::*` relationship types (Strict namespace URIs match Transitional by final segment).
  - `src/ooxml/docx.rs` — `read(&[u8]) -> Document`, `write(&Document) -> Vec<u8>`; model `Document { title, blocks, images, notes }`, `Block::{Heading, Paragraph, List{ordered,start,items}, Code{lang,text}, Quote, Table{header,rows}, Rule, PageBreak}`, `Inline::{Text{text,style}, Link{href,children}, Image(i), Break, NoteRef(n)}`, `Style{bold,italic,underline,strike,code}`; `normalize_inlines`, `inline_text`, `image_pixels` (PNG / GIF / JPEG headers).
  - `src/ooxml/xlsx.rs` — `read` → `Workbook { sheets: [Sheet { name, state, rows: [[Cell]] }] }`, `read_sheet`, `sheet_names`, `write(&[WriteSheet])`, `write_table`, `Cell::{Empty, Text, Number, Bool, Error, Date(ISO 8601)}`, `serial_to_iso`, `iso_to_serial`, `format_kind`, `col_index` / `col_letters` / `parse_ref` / `cell_ref`, `encode_xstring` / `decode_xstring`.
- **Conformance:**
  - `cargo test --test opc` — 6 tests on LibreOffice-written .xlsx / .docx and on our writer: content-type lookup (Override then Default), package / part relationships, external hyperlink targets, image part bytes, case-insensitive part names, Strict relationship types.
  - `cargo test --test xlsx` — 8 tests: LibreOffice-written workbooks (two sheets, shared strings with Unicode, cached formula values incl. a `str` result and `#DIV/0!`, date / date-time / time formats, percent, a merged range, a multi-paragraph cell, `dateCompatibility="false"`); every day 1900-03-01 → 2100 round-trips serial ↔ ISO; the fictitious 1900-02-29 (serial 60); the 1904 system; 12 number-format classifications; our writer read back cell by cell; **LibreOffice opens our output** (`soffice --convert-to csv`, every sheet) and the CSV matches.
  - `cargo test --test docx` — 5 tests: a LibreOffice-written document read construct by construct (Heading 1–3 by style and level 4 by outline level only, bold / italic / underline / strike / monospace runs, a hyperlink whose Hyperlink style is not mistaken for underline, nested bullet and ordered lists, a table with a gridSpan merge, a two-line code block, a quote, an inline picture with alt text and size, a page break, a footnote, dc:title); a 15-block synthetic document (3-level mixed lists, a list starting at 3 and one restarting at 1, code with a language, blank code line, header table with a cell break, rule, anchor link, two notes, one with a hyperlink) survives write → read exactly and model → docx → model is stable; **LibreOffice opens our output**: PDF export succeeds and LibreOffice's own re-save of our .docx reads back with the headings, nested lists, list start 3, table, code, picture, both notes and the title.
  - Fixtures: `tests/data/ooxml/` written by LibreOffice 24.2.7.2 from our own sources embedded in `tools/make-office-fixtures.sh` (black box; program output carries no third-party licence).
- **Behaviour choices:** formulas are never evaluated — the cached value is read; a number whose format is a date or time becomes `Cell::Date` (ISO text); elapsed-time formats (`[h]:mm`) and percentages stay numbers; booleans written by LibreOffice as numbers with a BOOLEAN format read as numbers (what the file says); merged ranges keep their value in the top-left cell.
- **Write subset (xlsx):** shared strings, numbers, booleans, errors, dates as serials with `yyyy-mm-dd` / `yyyy-mm-dd hh:mm:ss` / `hh:mm:ss` formats, bold frozen header row, column widths (given or sized from content), autofilter + `_xlnm._FilterDatabase`, sheet names sanitised to §18.2.19 rules and made unique. Stored ZIP (no compression).
- **docx choices:** every code block is one `w:sdt` tagged `code:<lang>` (so two blocks in a row stay two); quotes are wrapped in `omnidoc:quote` and a list item's further blocks (code, tables, extra paragraphs) in `omnidoc:item:<level>` so Markdown structure reads back exactly — all valid WordprocessingML structured document tags (§17.5.2), ignored visually by Word and LibreOffice; documents without the tags read by style; horizontal rules are an empty paragraph with a bottom border; footnotes and endnotes merge into one note list in reference order; a cell's paragraphs join with line breaks; merged cells are empty cells; numbered headings stay headings.
- **Known gaps (docx):** text boxes and shapes (`mc:AlternateContent`) are skipped; comments, headers / footers, fields other than HYPERLINK, equations (OMML), charts and embedded objects are not read; table cell spans are not written (cells are plain); list start values only for level 0 of each instance; no `.doc` (binary) — out of scope.
- **Known gaps (xlsx):** no formula writing; no cell styles beyond the five above; no charts, comments, data validation, conditional formats, pivot tables; no `.xls` (BIFF) — out of scope until real files arrive (OFFICE-FORMATS-0 decision).
- **Patent note:** ECMA-376 / ISO/IEC 29500 are covered by Microsoft's Open Specification Promise (Microsoft Open Specifications Dev Center; ECMA-376 / ISO/IEC 29500 are listed among the covered specifications), a promise not to assert patents against conforming implementations — URL to be pinned at release. Release gate 3: recorded; counsel FTO not required for a spec-conformant reader/writer but remains J's call before release.
